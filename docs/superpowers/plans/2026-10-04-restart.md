# Restart from Config Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Config gets a two-press RESTART button that brings Acid OS back to its boot-time screen-size picker.

**Architecture:**
- **Platform:** `Platform::restart()` has a default of false. The hosted build starts a fresh copy of the program with the same command line minus `--screen`, then exits.
- **Kernel and API:**
  - `Kernel::restart()` calls the platform;
  - `AcidApi::restart()` is a required method, and it refuses carts;
  - the Lua binding is `acid_restart()`.
- **Config:** a SYSTEM section with the button. It arms on the first press, restarts on the second, and disarms after 3 s or on a press elsewhere.

**Tech Stack:** Rust 2024 workspace (`v3/`) and Lua 5.4 apps.

**Spec:** `docs/superpowers/specs/2026-10-04-restart-design.md`

## Global Constraints

- **Repo and cargo:** paths are relative to `/home/norfolkh/acid-os-v3`. Cargo commands run from `v3/`.
- **Carts:** a cart's `restart()` is always false and never reaches the platform (spec §16.2).
- **Wasm:** no new import, and `IMPORT_NAMES` is unchanged.
- **Config:**
  - the window is 180×242, and the existing coordinates are unchanged;
  - the button is at `(4, 212, 172, 20)`;
  - it is armed for 3000 ms;
  - armed, it reads `SURE? PRESS AGAIN` on `0xB026FF`;
  - after a refused restart it reads `RESTART FAILED`.
- **Assertion counts:** pinned in `game_tests.rs`. The `config` suite goes from 18 to 28.
- **Goldens:** no golden shows Config. If a golden test fails, stop and report it.
- **Commits:** every commit message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## How the code is given

The diffs were built and tested together: `cargo test --workspace` gave 538 passed, 0 failed. They apply cleanly to the plan's commit. After applying, run the stated tests. Then do the stated **RED check**, which is a temporary mutation that must make a named test fail, and revert it before committing.

## Ruling recorded in the plan

Spec §5 lists "the default `restart` returns false". There's no lightweight `Platform` implementor in which to test the default, since `FakePlatform` overrides it and `HostedPlatform` re-executes. So the default is a one-line `false` covered by reading, not by a test. If this is wrong, the cost is a future platform silently inheriting "can't restart", which is the safe failure.

+//! Restarting the hosted OS: start a fresh copy of this program, which
+//! opens at the screen-size picker, then exit. The new copy gets the same
+//! command line minus any `--screen`, so the picker shows again; every
+//! other argument (`--app tetris`, say) carries over.
+
+/// The arguments for the fresh copy: `args` (without the program name) with
+/// `--screen <size>` and `--screen=<size>` removed, everything else in order.
+pub fn restart_args(args: impl IntoIterator<Item = String>) -> Vec<String> {
+    let mut out = Vec::new();
+    let mut it = args.into_iter();
+    while let Some(a) = it.next() {
+        if a == "--screen" {
+            it.next();
+        } else if !a.starts_with("--screen=") {
+            out.push(a);
+        }
+    }
+    out
+}
+
+/// Starts the fresh copy and exits this one. Returns false (after saying
+/// why on stderr) only if the copy couldn't be started.
+pub fn restart_process() -> bool {
+    let exe = match std::env::current_exe() {
+        Ok(exe) => exe,
+        Err(e) => {
+            eprintln!("Acid OS v3: restart: can't find this program: {e}");
+            return false;
+        }
+    };
+    match std::process::Command::new(exe).args(restart_args(std::env::args().skip(1))).spawn() {
+        Ok(_) => std::process::exit(0),
+        Err(e) => {
+            eprintln!("Acid OS v3: restart: can't start a new copy: {e}");
+            false
+        }
+    }
+}
