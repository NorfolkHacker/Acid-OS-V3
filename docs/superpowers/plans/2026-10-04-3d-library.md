# 3D Library Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Lines, triangles and spinning 3D meshes for Lua apps and wasm carts, through one integer-only renderer in `acid-gfx`, plus a new showcase app, Acid Spin.

**Architecture:**
- `acid-gfx` gains `raster.rs` (line, triangle) and `three_d.rs`: a sine table, transforms, `Mesh`, built-in shapes, `draw_mesh` and `mesh_cost`.
- `acid-api` gives each running app a mesh store, and six `AcidApi` methods plus a fuel-cost query.
- Lua and wasm expose the six calls.
- Acid Spin is a Lua `AcidGame` on top.

**Tech Stack:** Rust 2024 workspace (`v3/`, no_std + alloc for `acid-gfx`/`acid-api`), mlua 0.10, wasmi 2.

**Spec:** `docs/superpowers/specs/2026-10-04-3d-library-design.md`

- **Indices:** 1-based in Lua and 0-based in wasm. In wasm a face is 4 i32s, with −1 in the 4th slot for a triangle.

- [ ] **Step 2: Implement**

    5. Sort by `za + zb + zc` of the rotated points, descending (farthest first).
    6. `fill_triangle` with each channel `(ch·light) >> 8`.
  - **Both:** solid, then wire in the brightened colour.
  - **`mesh_cost`:** use the same `prepare` and the same culling, and sum as the tests specify. The cost is in pixels, before bytes-per-pixel scaling.
